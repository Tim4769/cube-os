In n8n, I wanted to set up two ChatGPT agents. One agent would argue against an idea, and the other would argue for it. However, the workflow ended up running twice, which was not ideal. Because of that, I started testing different methods, such as using split nodes, merge nodes, and changing key names.

At first, renaming the keys worked well. I gave the first output one name and the second output a different name, so the third ChatGPT agent could recognize them as two separate pieces of text. Without changing the key names, both outputs had the same name, so the third ChatGPT agent would treat them as the same input.

However, I felt that changing the key names was a little sketchy, so I kept looking for a better method. I tried using different nodes to combine the outputs into one larger list or into lists with different names. My goal was for the third ChatGPT agent to clearly recognize the two different outputs.

After multiple trials, I ended up using a merge node with the mode set to “combine.” I used “combine by position” with two inputs from the two ChatGPT agents. For clash handling, I selected the option to always add the input number to field names when field values clash. This allowed the two outputs to merge into one larger list while still keeping their field names different.

This method worked because the third ChatGPT agent could now receive and identify both outputs separately. It could use one response from the agent arguing for the idea and another response from the agent arguing against it.
