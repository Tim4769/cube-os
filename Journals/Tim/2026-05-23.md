Software basics
* #include <> includes a library that contains objects, functions, constants, or even other liberary, etc that is written by someone else
* Function: a set of codes that was written by someone else and can be easily implemented by others, like void setup() {}, which is in the Arduino library
* A void in front of a function means the function doesn't return a value; it returns void, which is nothing. It can be used when I want to turn a LED on and I can see the LED on so I dont need something to be returned from the function
* namespace, like NameOfSpace {, creates something like a folder in the code itself, which allows functions that have the same name to be called and can shorten function names when code becomes complicated, such as Camera::start();, which calls the start function in the Camera namespace
* Objects have blueprints and the object itself. Blueprints are created using this: class Robot. Objects are created using Robot cube1;. 
    * Objects can store states like cube1.battery = 90; when running cube1.battery, it will return 90
    * Objects are often under namespaces since namespaces give the overall structure of the code, and objects store actual values and functions which can be called by NameSpace::Blueprint Object;
    * Objects have access specifiers, such as public, private, and protected.
    * A good example is Serial.begin(SERIAL_BAUD_RATE);, where the Serial is a object and begin() is a function inside the object. the Serial object is included in the Arduino liberary
* Types define the type of data that the variable stores or the function returns, such as int, float, string, etc
* const makes a variable unchangeable after it is defined. const int age = 17; you cannot do age = 18 since it has a const when defined
* A compiler turns commands from the programming language as a whole, such as C++, into machine code that can be run by the CPU or microcontroller. The compiler compiles the whole machine code during build time
* An interpreter runs commands line by line and moves to the next line after the last one, unlike a compiler. Examples of languages using an interpreter are Python. An interpreter interprets the code line by line at run time
